## 1. Юу хаана ажиллах вэ

```
   Отгоогийн браузер (Улаанбаатар)
        │  https://jiguur-zam.vercel.app
        ▼
   ┌─────────────────────────────────────────────────────────┐
   │ Vercel CDN — 126 PoP, TLS, статикийг ХАМГИЙН ОЙРООС     │
   │   /            → index.html  ┐                          │
   │   /assets/*    → JS, CSS     ├─ `system/frontend/dist`   │
   │   /favicon.png → зураг       ┘  (build-ийн гаралт)      │
   └───────────────┬─────────────────────────────────────────┘
                   │  /api/*  (rewrites: → /api/index)
                   ▼
   ┌─────────────────────────────────────────────────────────┐
   │ Python функц `api/index.py` — region **sin1** (Сингапур) │
   │   · `system/backend/app/main.py:app` (FastAPI, ASGI)     │
   │   · PDF-ийн фонт: `system/backend/assets/fonts/*.ttf`    │
   │   · дээд ажиллах хугацаа 300 сек                         │
   └───────────────┬─────────────────────────────────────────┘
                   │  postgresql+psycopg://…-pooler…?sslmode=require
                   ▼
   ┌─────────────────────────────────────────────────────────┐
   │ Neon Postgres — AWS ap-southeast-1 (Сингапур)            │
   │   бүх өгөгдөл + хавсралтууд (bytes) + аудит              │
   └─────────────────────────────────────────────────────────┘

   Vercel Cron ── өдөр бүр 22:00 UTC = 06:00 Улаанбаатар ──►
        GET /api/cron/daily
        Authorization: Bearer $CRON_SECRET
```

**Функц ба өгөгдлийн сан НЭГ ХОТОД байх нь чухал.** Vercel өөрөө:
«Functions should be executed in the same region as your database, or as
close to it as possible, for the lowest latency»
([/docs/regions](https://vercel.com/docs/regions)). `sin1` = `ap-southeast-1`
= Сингапур — Neon-ы `aws-ap-southeast-1`-тэй ижил дата-төв.
Улаанбаатараас Сингапур хүртэл ~90 мс; Виржиниа (`iad1`, анхдагч) хүртэл
~230 мс — хүсэлт бүрд 3-5 удаа SQL явдаг тул зөрүү нь мэдрэгддэг.

## 3. Neon төсөл үүсгэх

```bash
# (1) Аль байгууллага дор үүсгэхээ мэдэх — org id нь `org-…` хэлбэртэй
neonctl orgs list

# (2) Төсөл — Сингапурт
neonctl projects create \
  --name jiguur-zam \
  --region-id aws-ap-southeast-1 \
  --org-id <ЭНД org id-ГАА ТАВИНА>
```

> `--org-id` нь ЗААВАЛ биш: ганц байгууллагатай бол Neon өөрөө сонгоно.
> Хэрэв «you have access to multiple organizations» гэж гарвал (1)-ийн
> жагсаалтаас хуулна.

Дараа нь **хоёр** холболтын мөр авна — хоёулаа хэрэгтэй, хоёр өөр зорилготой:

```bash
# POOLED — Vercel рүү. Функц бүр шинэ холболт нээдэг тул pooler заавал.
neonctl connection-string --project-id <project-id> --pooled

# DIRECT — энэ Mac-аас схем үүсгэх/дата ачаалахад (DDL нь pooler-гүй тогтвортой)
neonctl connection-string --project-id <project-id>
```

Pooled мөр нь `…-pooler.ap-southeast-1.aws.neon.tech…` гэсэн хэсэгтэй байна.
Хоёуланд нь `?sslmode=require` байгаа эсэхийг шалгана. Драйверын нэрийг
`postgresql+psycopg://…` болгож солино (SQLAlchemy 2 + psycopg 3).

## 5. Vercel төсөл үүсгэх

**Хяналтын самбараар:** vercel.com → Add New → Project → `Ulz11/jiguur`
импортлох → **Root Directory нь `.` (үндэс) хэвээр** → Deploy дарахаас
ӨМНӨ Environment Variables-аа тавина (6-р алхам).

**CLI-аар:**
```bash
npm i -g vercel
vercel login
cd /Users/vida/Desktop/Dev/jiguur
vercel link        # төсөл үүсгэх/холбох
```

Build-ийн тохиргоог `vercel.json` өөрөө агуулна — самбар дээр юу ч гараар
бичих шаардлагагүй:

| Түлхүүр | Утга | Яагаад |
|---|---|---|
| `installCommand` | `npm --prefix system/frontend ci` | Фронтенд нь дэд хавтаст; үндсэн `package.json`-ы Playwright dev-хамаарлыг татахгүй |
| `buildCommand` | `npm --prefix system/frontend run build` | `tsc -b && vite build` |
| `outputDirectory` | `system/frontend/dist` | Статикийг CDN тарааж эхлэх газар |
| `functions["api/index.py"].maxDuration` | `300` | Hobby-ийн ДЭЭД хэмжээ ([limits](https://vercel.com/docs/functions/limitations#max-duration)) |
| `functions[…].includeFiles` | `system/backend/**` | Backend ба PDF-ийн фонтыг bundle-д оруулна |
| `regions` | `["sin1"]` | Neon-той нэг хотод |
| `crons` | `/api/cron/daily` @ `0 22 * * *` | 06:00 Улаанбаатар |
| `rewrites` | `/api/(.*)` → `/api/index`, `/(.*)` → `/index.html` | API + SPA |

> `functions.runtime`-ыг ЗОРИУДААР тавиагүй. Тэр талбар нь «npm package
> name of a Runtime» — зөвхөн албан ёсны бус (community) runtime-д хэрэгтэй
> ([vercel.json → functions](https://vercel.com/docs/project-configuration/vercel-json#functions)).
> Python нь албан ёсных; хувилбарыг `.python-version` (`3.12`) заана
> ([python-version](https://vercel.com/docs/functions/runtimes/python/python-version)).

## 6. Environment Variables

Vercel самбар → Settings → Environment Variables. **Production** орчинд бүгд.

| Нэр | Утга | Нууц уу |
|---|---|---|
| `DATABASE_URL` | Neon-ы **POOLED** мөр (`postgresql+psycopg://…-pooler…?sslmode=require`) | **ТИЙМ** |
| `JIGUUR_SECRET` | 32+ тэмдэгтийн санамсаргүй мөр (`openssl rand -hex 32`) | **ТИЙМ** |
| `CRON_SECRET` | 16+ тэмдэгтийн санамсаргүй мөр | **ТИЙМ** |
| `JIGUUR_ENV` | `prod` | үгүй |
| `JIGUUR_ALLOWED_ORIGINS` | `https://jiguur-zam.vercel.app` (эцсийн домэйн) | үгүй |

**Тавихгүй зүйлс:** `JIGUUR_AUTO_INIT` (Vercel дээр схем автоматаар
үүсгэхгүй — 4-р алхам гараар хийгдсэн), `JIGUUR_TODAY` (зөвхөн тест).

`CRON_SECRET`-ийн тухай Vercel: «The value of the variable will be
automatically sent as an `Authorization` header when Vercel invokes your
cron job… The `authorization` header will have the `Bearer` prefix for the
value»
([manage-cron-jobs](https://vercel.com/docs/cron-jobs/manage-cron-jobs#securing-cron-jobs)).

CLI-аар:
```bash
vercel env add DATABASE_URL production
vercel env add JIGUUR_SECRET production
vercel env add CRON_SECRET production
vercel env add JIGUUR_ENV production            # prod
vercel env add JIGUUR_ALLOWED_ORIGINS production
```

## 8. Утсаа шалгах (smoke test)

```bash
BASE=https://jiguur-zam.vercel.app

# 1. Амьд эсэх
curl -s $BASE/api/health

# 2. Нэвтрэх — otgoo
curl -s -X POST $BASE/api/auth/login \
     -H 'Content-Type: application/json' \
     -d '{"username":"otgoo","password":"1234"}'
#   → token авна. Дараах хүсэлтүүдэд: -H "Authorization: Bearer $TOKEN"

# 3. Cron — нууц үггүйгээр 401, нууц үгтэйгээр 200
curl -s -o /dev/null -w '%{http_code}\n' $BASE/api/cron/daily
curl -s -H "Authorization: Bearer $CRON_SECRET" $BASE/api/cron/daily
```

Браузераар:

1. `$BASE` нээгээд `otgoo` / `1234`-өөр нэвтэрнэ.
2. **Удирдлагын төв: харилцагч 10, гэрээ 15** — энэ хоёр тоо буруу бол
   4-р алхам дутуу гүйсэн, цааш явахгүй.
3. Харилцагчийн профайл → **Тооцооны хуулга (PDF)** — кирилл үсэг зөв
   гарч байна уу. Гарахгүй бол `includeFiles` фонтыг аваагүй гэсэн үг
   (bundle доторх `system/backend/assets/fonts/`).
4. Хавсралт нэмэх (4 MB-аас бага) → **Татах** товч ажиллаж байна уу.
5. Эхний хүсэлт удаан (2-4 сек) байвал ХЭВИЙН — Neon-ы compute сэрж
   байна (§11).

## 9. Буцаах (rollback)

Хоёр давхарга **тусдаа** буцаана — код нь Vercel дээр, дата нь Neon дээр.

**Код:** Vercel → Deployments → өмнөх амжилттай deploy → **Instant
Rollback**. Хэдэн секунд.

> ⚠ Cron нь буцахгүй: «If you Instant Rollback to a previous deployment,
> active cron jobs **will not** be updated»
> ([manage-cron-jobs](https://vercel.com/docs/cron-jobs/manage-cron-jobs#rollbacks-with-cron-jobs)).

**Дата:** Neon-ы PITR — салбарыг тодорхой АГШИН руу буцаана.
```bash
# Юу болсныг эхлээд ХАРАХ: тухайн агшны хуулбар салбар үүсгэнэ
neonctl branches create --project-id <id> --name rescue \
        --parent main --timestamp 2026-09-06T02:30:00Z

# Тэр салбарын холболтоор шалгаад, зөв бол production-ыг сэргээнэ
neonctl branches restore main rescue --project-id <id>
```
`branches create --timestamp` нь **юуг ч устгахгүй** — тиймээс эхлээд
үргэлж түүгээр харна.

## 10. Нөөц

| Давхарга | Хэн хийдэг | Хэр удаан хадгалагдана |
|---|---|---|
| Neon PITR | **автоматаар** | Free: 6 цаг · Launch: 7 хоног · Scale: 14 хоног (тарифаа Neon самбараас шалга) |
| 7 хоногийн `pg_dump` | **хүн** (доорх тушаал) | Хэдэн ч удаан — оффисоос ГАДНА |

```bash
# 7 хоногт нэг удаа, DIRECT URL рүү. Файл нь ~5-20 MB.
pg_dump "postgresql://…DIRECT…?sslmode=require" \
        --format=custom --no-owner \
        --file="jiguur-$(date +%Y-%m-%d).dump"

# Сэргээх (шинэ хоосон сан руу):
pg_restore --dbname="postgresql://…" --no-owner jiguur-2026-09-06.dump
```

Гарсан файлыг **оффисын компьютер дээр БИШ** газар (Google Drive, гадаад
диск) хадгална. PITR нь Neon-ы дотор — Neon-ы бүртгэл өөрөө алдагдвал
тэр нь ч хамт алга болно.

## 11. Тариф ба хязгаар

| Юу | Hobby (үнэгүй) | Pro |
|---|---|---|
| Функцийн дээд хугацаа | **300 сек** (анхдагч ба дээд) | 300 анхдагч, **800** дээд ([limits](https://vercel.com/docs/functions/limitations#max-duration)) |
| Хүсэлтийн биетийн хэмжээ | **4.5 MB** — хэтэрвэл 413 `FUNCTION_PAYLOAD_TOO_LARGE` | ижил 4.5 MB |
| Cron-ы давтамж | **өдөрт НЭГ удаа**; илүү бол deploy УНАНА | минут тутам |
| Cron-ы нарийвчлал | ±59 минут (цагийн дотор хэзээ ч) | яг тэр минутад |
| Cron-ы тоо | 100 | 100 |
| Функцийн санах ой | 2 GB | 4 GB хүртэл |
| Bundle | 250 MB (Python: **500 MB**) | ижил |
| Region | нэг л region сонгож болно (`sin1` болно) | олон |

Эх сурвалж: [functions/limitations](https://vercel.com/docs/functions/limitations),
[cron-jobs/usage-and-pricing](https://vercel.com/docs/cron-jobs/usage-and-pricing).

**Бидний хувьд юу гэсэн үг вэ:**
- Өдөр бүрийн cron (`0 22 * * *`) нь өдөрт нэг удаа тул **Hobby дээр ч
  ажиллана**. Гэхдээ Hobby дээр 06:00-07:00 хооронд ХЭЗЭЭ Ч цохиж болно —
  нэхэмжлэлийн огноо нэг цагаар хөвөх нь тооцоонд нөлөөлөхгүй.
- Хавсралтын хаалга **4 MB** (`system/frontend/src/lib/upload.ts`) —
  4.5-ын оронд 4 болгосон нь `multipart` нь файлын дээр толгой нэмдэгтэй
  холбоотой.
- Excel экспорт, PDF нь 300 секундэд бялхам багтана.

**Neon-ы үнэгүй тариф:** compute нь ~5 минут ажиллаагүй бол ӨӨРӨӨ унтарна
(autosuspend). Дараагийн хүсэлт нь түүнийг сэрээнэ — **эхний хариу 1-4
секунд удаан**, дараагийнх нь хэвийн. Отгоо өглөө 9-д эхний хуудсаа
нээхэд «жоохон удаж байна» гэж мэдрэх нь ЭНЭ. Тэр нь ажилд саад болбол:
Neon-ы тарифаа өсгөж autosuspend-ыг унтраах, эсвэл cron-ыг өглөө 8:45-д
нэг удаа цохиулж «сэрээж» болно.

## 13. Локал ажиллагаа (хөгжүүлэгчид)

`system/frontend/dist` нь **git дотор БАЙХГҮЙ** болсон (build-ийн гаралт,
эх код биш). Backend нь локал дээр түүнийг үйлчилдэг тул **шинэ хуулбар
татсаны дараа нэг удаа build хийнэ**:

```bash
npm --prefix system/frontend ci
npm --prefix system/frontend run build      # → system/frontend/dist
```

Үүний дараа `.claude/launch.json`-ы `jiguur` (эсвэл `jiguur-top10`)
тохиргоо урьдын адил `http://localhost:8000` дээр бүтэн аппыг үзүүлнэ.
Зөвхөн фронтендыг халуунаар засах бол `jiguur-web` (`:5173`, `/api` нь
`:8000` руу прокси хийгдэнэ). E2E (`npx playwright test`) нь мөн тэр
`dist`-ийг ашигладаг — **build хийхгүйгээр E2E унана**.

CI дээр энэ алхмыг `.github/workflows/playwright.yml` дотор нэмсэн.

## 14. Тэмдэглэл — яагаад ингэж хийсэн бэ

**`api/index.py` дотор адаптер алга.** Vercel-ийн Python runtime нь
`/api` доторх файлын дээд түвшний `app` хувьсагчийг ASGI апп гэж ШУУД
ачаална: «Each `.py` file must define one of these top-level names: `app`
for an ASGI or WSGI application»
([api-directory](https://vercel.com/docs/functions/runtimes/python/api-directory)).
`mangum` шаардлагагүй.

**Яагаад `api/index.py` болов, `app.py` биш вэ.** Vercel нь үндэс дэх
`app.py`/`main.py`/`index.py` зэргийг олбол **framework preset** асааж,
«the framework application handles all requests, and files under `/api`
don't become separate Vercel Functions» гэж ажиллана. Бидэнд статик
фронтенд + ганц API функц хэрэгтэй тул entrypoint-ыг зөвхөн `/api` дотор
байлгаж, `vercel.json`-д `"framework": null` («Other») гэж бичив.

**Rewrites нь статикийг дардаггүй.** `/(.*)` → `/index.html` дүрэм нь
Vercel-ийн албан ёсны SPA жишээ ([vercel-json →
rewrites](https://vercel.com/docs/project-configuration/vercel-json#rewrites));
rewrite нь файлын систем ОНОГДООГҮЙ үед л ажилладаг тул `/assets/…` шууд
үйлчлэгдэнэ. Дараалал чухал: `/api/(.*)` нь `/(.*)`-аас ӨМНӨ.

**CSP толгой тавиагүй.** Апп нь PDF/Excel-ээ `blob:` URL-аар нээдэг
(`api.ts` → `openPdf`, `downloadFile`); хатуу `default-src 'self'` нь
түүнийг чимээгүй хаана. Бусад хамгаалалтын толгойнууд (`nosniff`,
`X-Frame-Options: DENY`, HSTS, `Referrer-Policy`) `vercel.json`-д байна.

**`installCommand` нь `npm --prefix system/frontend ci`.** Үндсэн
`package.json`-ы Playwright dev-хамаарлыг Vercel дээр татах шалтгаангүй.
`installCommand` + `buildCommand` хоёр НИЙЛЭЭД
`npm --prefix system/frontend ci && npm --prefix system/frontend run build`
болно — хоёр тусдаа алхам болгосон нь `npm ci`-г ХОЁР УДАА гүйлгэхээс
хамгаална (`ci` нь `node_modules`-ыг бүхэлд нь устгаад дахин татдаг).
Python-ы хамаарлыг runtime өөрөө root `requirements.txt`-ээс суулгана —
энэ нь төслийн Install Command-аас ТУСДАА алхам.

## 15. Юу шалгаагүй вэ (эхний deploy дээр батлах)

1. `functions.includeFiles` нь `system/backend/**`-ийг Python bundle-д
   ЯГ ХЭРХЭН оруулахыг баримт бичиг нарийн тайлбарлаагүй; Python runtime
   нь аль хэдийн «include all files from your project that are reachable
   at build time» гэдэг тул энэ нь давхар баталгаа. **Батлах арга:**
   эхний deploy-ын дараа PDF гаргах (фонт олдвол зөв).
2. `rewrites`-ийн `/api/index` гэсэн зорилго — баримт бичигт `api/index.py`
   нь `/api` замд суудаг гэж бичсэн. Хоёр зам ижил функц рүү очих ёстой.
   **Батлах арга:** `curl $BASE/api/health` 200 буцаах.
3. Root `requirements.txt` дэх `-r` нь Vercel-ийн суулгагчид ажиллах эсэх.
   **Батлах арга:** build-ийн лог. Ажиллахгүй бол `system/backend`-ийн
   жагсаалтыг root руу ХУУЛНА (давхардал үүснэ — сүүлийн арга).
4. `.vercelignore` нь **GitHub-аар** хийгдсэн deploy дээр ч мөрдөгддөг
   эсэхийг баримт бичиг тодорхой бичээгүй (тэнд «when uploading your
   project» гэсэн үг л байна). **Аюулгүй байдлын хувьд энэ нь чухал биш:**
   бодит харилцагчийн дата агуулсан бүх файл (`real_data.json`, `.secret`,
   `*.db*`, `Тулгалтын тайлан.md`) нь ХЭДИЙНЭЭ `.gitignore`-т байгаа тул
   git-д огт байхгүй → Vercel хэзээ ч харахгүй. `.vercelignore` нь зөвхөн
   bundle-ын хэмжээ, хурдны давхар баталгаа.

## 16. Үндсэн `requirements.txt` — `-r` ажиллахгүй (2026-09-06)

Vercel-ийн Python задлагч `-r <файл>` оруулгыг ойлгодоггүй: анхны байршуулалт
«could not parse requirements.txt … at position 339» гэж уналаа (урд тал нь
амжилттай баригдсаны дараа). §15.3-т эргэлзээтэй гэж тэмдэглэсэн зүйл нь
БАТЛАГДАВ — жагсаалт үндэс дээр БҮТНЭЭР бичигдэнэ.

Тиймээс хамаарлын жагсаалт ХОЁР файлд амьдарна:

| Файл | Хэн уншдаг | Ялгаа |
|---|---|---|
| `requirements.txt` (үндэс) | Vercel-ийн функц | `uvicorn` БАЙХГҮЙ — тавцан өөрөө ASGI-г үйлчилнэ |
| `system/backend/requirements.txt` | оффисын `run.bat`, локал dev | `uvicorn[standard]` ОРНО |

Багц нэмэх/солиход ХОЁУЛАНГ нь засна.
